# Sparkle Auto-Update via GitHub Releases

## Goal

Replace the current "git clone + cp" distribution model with a Sparkle 2 auto-update flow backed by GitHub Releases. Users download the `.zip` once from a GitHub Release; all subsequent updates are handled in-app by Sparkle (check → download → replace → relaunch).

## Constraints

- **Ad-hoc signed** — no Developer ID, no notarization. Sparkle's EdDSA (ed25519) signature is the sole integrity check.
- **macOS 13+** — Sparkle 2.x supports this.
- **No CI** — the release workflow is fully manual (local build → tag → `gh release create`).
- **Sandbox OFF** — already the case; Sparkle needs network + file-system access, which is available.

## Architecture

### Sparkle Integration

Sparkle 2 is added as an **SPM dependency** via `project.yml`'s `packages` + target `dependencies` fields. No CocoaPods, no Carthage.

Key Info.plist entries (added via `project.yml` → `info.properties`):

| Key | Value |
|---|---|
| `SUFeedURL` | `https://raw.githubusercontent.com/CoderZCC/VPNMenuBar/main/appcast.xml` |
| `SUPublicEDKey` | The ed25519 public key generated by `generate_keys` |
| `SUEnableAutomaticChecks` | `true` |

### Controller Setup

`AppCoordinator` owns a `SPUStandardUpdaterController` instance (initialized once at launch). This controller manages:

- Background scheduled checks (default: every 24 hours, configurable by Sparkle)
- The standard Sparkle update UI (alert → progress → relaunch prompt)

`MenuContentView` exposes a **"Check for Updates"** menu item that calls `updaterController.checkForUpdates(nil)`.

### appcast.xml

A standard Sparkle appcast file at the repository root. Format:

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>VPN MenuBar</title>
    <item>
      <title>Version X.Y.Z</title>
      <sparkle:version>N</sparkle:version>
      <sparkle:shortVersionString>X.Y.Z</sparkle:shortVersionString>
      <description><![CDATA[<ul><li>Release notes here</li></ul>]]></description>
      <pubDate>Mon, 13 Apr 2026 00:00:00 +0800</pubDate>
      <enclosure
        url="https://github.com/CoderZCC/VPNMenuBar/releases/download/vX.Y.Z/VPNMenuBar-X.Y.Z.zip"
        type="application/octet-stream"
        sparkle:edSignature="BASE64_EDDSA_SIGNATURE"
        length="FILE_SIZE_IN_BYTES"
      />
    </item>
  </channel>
</rss>
```

Each release adds a new `<item>` block at the top. Sparkle compares `sparkle:version` (build number) against the running app's `CFBundleVersion` to decide whether an update is available.

### Release Workflow (Manual)

```
1. Bump CFBundleShortVersionString and CFBundleVersion in project.yml
2. xcodegen generate
3. xcodebuild -project VPNMenuBar.xcodeproj -scheme VPNMenuBar \
     -destination 'platform=macOS' -configuration Release clean build
4. Copy built .app to repo root:
     APP_SRC="$(xcodebuild ... -showBuildSettings | awk '/CODESIGNING_FOLDER_PATH/ {print $2}' | head -1)"
     cp -R "$APP_SRC" ./VPNMenuBar.app
5. ditto -c -k --keepParent ./VPNMenuBar.app ./VPNMenuBar-X.Y.Z.zip
6. Sign the zip with Sparkle's sign_update tool:
     ./sign_update VPNMenuBar-X.Y.Z.zip
   → outputs the edSignature and file length
7. Update appcast.xml with the new <item> (version, signature, length, download URL, release notes)
8. git add . && git commit && git tag vX.Y.Z && git push --tags
9. gh release create vX.Y.Z VPNMenuBar-X.Y.Z.zip --title "vX.Y.Z" --notes "..."
```

## File Changes

| File | Change |
|---|---|
| `project.yml` | Add Sparkle SPM package + target dependency; add `SUFeedURL`, `SUPublicEDKey`, `SUEnableAutomaticChecks` to Info.plist properties |
| `VPNMenuBar/App/VPNMenuBarApp.swift` | `AppCoordinator` creates and holds `SPUStandardUpdaterController`; expose it to `MenuContentView` |
| `VPNMenuBar/UI/MenuContentView.swift` | Add "Check for Updates" button calling `updaterController.checkForUpdates(nil)` |
| `appcast.xml` (new) | Initial appcast with v0.2.0 entry |
| `INSTALL.md` | Add "Auto-Update" section; update install instructions to point to GitHub Releases |
| `README.md` | Update install instructions; mention auto-update |

## Out of Scope

- GitHub Actions / CI automation
- DMG packaging
- Homebrew Cask
- Delta updates (require Developer ID codesigning)
- Changes to VPN core logic, Config schema, or dependency installer
- Removing the in-tree `VPNMenuBar.app/` (backward compatibility for existing users)
